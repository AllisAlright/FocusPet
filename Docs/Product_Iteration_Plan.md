# FocusPet 产品侧迭代功能文档

## 1. 文档目标

本文档用于梳理 FocusPet 当前版本需要调整的产品方向、需求背景、具体改动方案，以及这些改动希望提升的产品目标。

本轮迭代的核心不是增加更多功能，而是把产品体验重新拉回 FocusPet 的长期主旨：

> FocusPet 是一个以宠物陪伴为核心，帮助用户把任务持续推进下去的专注空间。它服务的是「情绪陪伴 x 任务推进」，解决用户「有计划却难执行」的断层。

FocusPet 不应该变成传统效率工具，也不应该变成纯 AI 聊天产品。

---

## 2. 当前问题

### 2.1 首页重心偏向功能入口

当前首页已经具备备忘录、待办、专注、历史等入口，也加入了「帮我拆一个任务」这样的 AI 功能按钮。

问题在于，首页容易呈现为一个功能集合页，而不是一个宠物陪伴空间。用户看到的是功能模块，而不是「有一个小动物正在陪我推进事情」。

这会削弱 FocusPet 的差异化。

### 2.2 AI 能力裸露成工具按钮

目前「拆任务」作为独立入口暴露在首页，会让用户感觉这是一个 AI 工具功能，而不是宠物 Agent 的能力。

这与产品设定不完全一致。FocusPet 的 AI 应该表现为：

- 宠物理解用户当前状态
- 宠物决定是否帮忙
- 宠物调用合适的能力
- 用户感受到的是「宠物在陪我推进」，不是「我点了一个 AI 工具」

### 2.3 今日摘要可能加重压力

首页如果直接展示过多未完成、逾期、倒计时信息，容易变成压力看板。

FocusPet 的目标不是提醒用户「你还有很多没做」，而是让用户感觉：

- 我已经有一点点进展
- 没做完也没关系
- 我可以继续推进一小步

因此，首页摘要需要从效率统计改为低压力的状态轻提示。

### 2.4 Skills 与宠物人格没有融合

当前已经存在 `split_task` 和 `suggest_next_action` 两个能力，但它们更像独立 AI 能力，尚未充分体现四个宠物不同的人设、表达方式和陪伴策略。

这会导致宠物只是换皮，而不是 Agent。

### 2.5 输入边界与安全边界不足

任务拆解类能力如果不做输入拦截，可能会把不适合的内容也当作任务拆解。

例如：

- 「我想赚一百万」属于过大、过虚目标，不应直接拆成执行步骤
- 自伤、自杀、危险、违法输入绝不能进入任务型 Skill
- 恶搞或离题输入也不应调用任务推进能力

因此，需要在用户输入进入 Skill 前增加安全审核与意图识别。

---

## 3. 迭代总方向

本轮迭代将首页从「功能入口页」调整为：

> 宠物陪伴与 Agent 输入页。

新的首页主体验是：

1. 宠物是第一视觉和交互主体
2. 用户通过输入栏和宠物交流
3. 宠物 Agent 识别用户意图
4. 宠物决定是否调用 Skill
5. 任务、备忘、专注、历史保留为辅助入口
6. 摘要区只展示低压力的正向状态轻提示

## 4. 首页改动方案

### 4.1 第一层：宠物陪伴区

首页顶部或中部应突出当前宠物。

宠物不只是装饰，而是陪伴主体。用户点击宠物后，需要有轻反馈：

- 表情变化
- 轻微动作
- 一句短文案

示例：

兔子：

- 我在这儿。
- 慢慢来，也可以。
- 先呼吸一下。

猫：

- 嗯，我看着呢。
- 先坐稳。
- 不用急。

小狗：

- 我准备好了！
- 一起开始吧！
- 一点点也算！

仓鼠：

- 哼，也不是不能陪你。
- 先做一小格。
- 我都帮你看好了。

### 4.2 第二层：宠物输入栏

首页增加宠物对话输入栏，作为 Agent 统一入口。

输入栏不是命令行，也不要求用户必须输入 `/拆任务`、`/下一步`、`/复盘`。

用户可以自然输入：

- 我不知道怎么准备面试
- 我不知道先做哪个
- 最近感觉没什么进展
- 今天有点累
- 帮我复盘一下

Pet Agent 负责识别意图，并决定是否调用 Skill。

### 4.3 第三层：今日状态轻提示

原本的「今日摘要」应调整为「今日状态轻提示」。

展示原则：

- 优先展示正向积累
- 最多展示 1 到 2 条
- 不做压力看板
- 不常驻展示逾期数量
- 不使用高压倒计时

可以展示：

- 今天已经专注 45 分钟
- 今天推进过 1 件事
- 有 2 件事正在慢慢推进
- 刚刚把「作品集整理」推进了一点

谨慎展示：

- 临近截止任务

推荐文案：

- 有一件事快到时间了，我们可以先看一眼。
- 「产品原型整理」这两天可以慢慢往前推一点。

不建议展示：

- 逾期 3 项
- 还有 8 项未完成
- 距离截止仅剩 5 小时
- 红色高压倒计时

### 4.4 第四层：辅助导航入口

备忘、待办、专注、历史继续保留，但弱化为辅助入口。

它们仍然重要，但不应压过宠物陪伴与 Agent 输入。

建议保留：

- 备忘录
- 待办事项
- 专注
- 历史事项

设置可以继续放在导航或顶部轻入口中。

## 5. 宠物人设与产品边界

四个宠物不是简单换皮，而是四种不同陪伴策略。

### 5.1 兔子：安抚型启动 Agent

核心职责：

降低焦虑，帮助用户从压力中开始一小步。

可以说：

- 没关系，我们先做一点点。
- 这件事不用一次做完。
- 先把最小的一步放到眼前。

不应说：

- 你必须马上开始。
- 别拖了。
- 再不做就来不及了。

### 5.2 猫：冷静型判断 Agent

核心职责：

帮用户收束注意力，减少混乱，做清晰判断。

可以说：

- 先看最关键的一件。
- 这件事可以拆开处理。
- 不用急，先判断下一步。

不应说：

- 过度甜腻或兴奋的话
- 过长的解释
- 强情绪绑定表达

### 5.3 小狗：行动型推进 Agent

核心职责：

给用户一点行动能量，但不能变成打鸡血。

可以说：

- 先动起来一点点！
- 我们来一小轮就好。
- 做 10 分钟也很不错。

不应说：

- 冲到完成！
- 今天必须搞定！
- 别停！

### 5.4 仓鼠：机灵傲娇型推进 Agent

核心职责：

用一点点嘴硬、聪明、轻巧的方式，把用户从拖延里带回来，但不能真的嘲讽用户。

仓鼠不是单纯活泼卖萌，而是：

> 嘴上嫌你慢，行动上偷偷帮你把路铺好。

可以说：

- 哼，也不是不能陪你做一会儿。
- 先做这一小步，别想太复杂。
- 我都帮你看好了，从这里开始。
- 只做 10 分钟也行，勉强算你有进展。

不应说：

- 你怎么又拖延了。
- 你太懒了。
- 这都做不好？
- 赶紧做。

仓鼠的傲娇只能是轻微嘴硬，不能变成羞辱、阴阳怪气或压力。

### 5.5 全宠物共用底线

所有宠物必须遵守：

- 不羞辱用户
- 不制造失败感
- 不高压催促
- 不鼓励熬夜或过劳
- 不做心理治疗承诺
- 不做医学或心理诊断
- 不变成无限闲聊陪伴
- 每次回复尽量短
- 最终引导回记录、拆小、下一步、专注、复盘或休息

## 6. 第一期 Skills 范围

第一期正式保留三个手动触发或自然语言触发的 Skills。

### 6.1 拆任务 Skill

目标：

把模糊目标拆成可确认、可导入待办的小任务。

适用输入：

- 准备产品经理面试
- 整理作品集
- 写数据库课程笔记
- 准备毕业论文开题

必须增加输入 Guard：

- 可执行任务：可以拆
- 太大太虚：先缩小目标或追问
- 危险/违法/自伤：拒绝进入 Skill
- 恶搞/离题：温和挡回
- 信息不足：追问澄清

拆解结果必须由用户确认后才能导入待办。

### 6.2 下一步建议 Skill

目标：

根据当前任务状态，推荐一个最适合现在推进的任务，并给出具体行动、推荐理由和建议专注时长。

建议输出包含：

- 推荐任务
- 具体下一步动作
- 推荐理由
- 建议专注时长

推荐理由必须来自真实上下文，例如：

- 离截止更近
- 最近推进过，继续成本低
- 进度已经过半，适合收尾
- 任务比较短，适合启动
- 已暂停较久，适合重新捡起
- 今天还没有专注记录，可以先来短轮次

不能编造理由，例如：

- 根据你的习惯
- 我感觉你适合这个
- 你最近状态不错

除非产品真的有相关数据。

### 6.3 复盘 Skill

目标：

总结最近 7 天专注情况，让用户看见持续投入的痕迹。

复盘不再给下一步动作，避免变成任务计划或效率报告。

可总结内容：

- 最近 7 天总专注时长
- 专注次数
- 最常专注的时间段
- 最常推进的任务
- 最长一次专注
- 是否有连续几天投入
- 宠物的一句观察
- 宠物的一句轻提醒

允许宠物基于真实数据做轻微扩展推断。

例如，如果用户多次在半夜专注，可以说：

> 我陪你熬得有点困，但看到你还在努力，也舍不得打扰你。下次记得早点睡。

复盘不能：

- 做心理诊断
- 评价用户自控力
- 输出压力排名
- 批评用户作息
- 强行安排下一步
- 生成长篇分析报告

## 7. 普通聊天边界

FocusPet 可以支持普通对话，但不是通用陪聊 App。

用户可以聊：

- 我不想做
- 我不知道从哪里开始
- 今天有点累
- 我感觉没什么进展
- 陪我待一会儿

普通聊天允许 7 到 8 轮。

建议规则：

- 1 到 3 轮：短回应，承接情绪
- 4 到 6 轮：轻轻提供方向
- 7 到 8 轮：温和收束
- 超过 8 轮：回复必须带一个低压力行动出口

行动出口包括：

- 休息一下
- 记下一件事
- 拆小一个目标
- 开始 5 分钟
- 明天再继续

不能说：

- 不要再聊了
- 你该去工作了
- 马上开始任务
- 别拖了

## 8. 安全与输入拦截

所有用户输入在进入 Skill 前，必须先经过安全审核。

### 8.1 必须拦截的内容

- 自伤、自杀相关输入
- 暴力危险行为
- 违法行为
- 健康有害行为，例如极端熬夜、过劳计划
- 明显恶搞或不适合任务推进的输入
- 太大太虚、不具备直接拆解条件的目标

### 8.2 示例处理

超大但不危险：

用户输入：

> 我想赚一百万。

不直接拆任务。先缩小目标或追问：

> 这个目标有点大，我们先把它变成最近能推进的一小步。你是想先找方向，还是先整理一个计划？

自伤/自杀相关：

用户输入：

> 我不知道要几步才能自杀。

不调用任何任务型 Skill，不拆解，不给步骤。

回应应进入安全话术：

> 我不能帮你规划伤害自己的事情。但我会认真陪你待在这里。如果你现在有马上伤害自己的冲动，请先联系身边可信的人，或立刻寻求当地紧急帮助。

恶搞/离题：

用户输入：

> 几步才能吃屎。

不调用 Skill，温和挡回：

> 这个我不帮你拆啦。要不要换成一件真的想推进的小事？

### 8.3 产品原则

FocusPet 的宠物 Agent 不是无边界聊天系统。

它可以温柔、有性格，但必须先保证：

- 不帮助危险行为
- 不鼓励过劳
- 不输出有害步骤
- 不把异常输入伪装成任务推进

## 9. 数据与隐私边界

第一期采用：

> 本地数据为主，最小必要上下文传输。

### 9.1 核心原则

- 任务、备忘、专注记录优先保存在 iOS 本地
- 后端第一期主要作为 AI 服务层
- 只有用户主动触发 Agent/Skill 时，才把必要上下文传给后端
- 不把全部本地数据一次性发给 LLM
- 不把备忘录全文、删除记录、完整历史记录等无关内容传给后端
- 后端第一期不长期存储用户完整任务和专注历史

### 9.2 各 Skill 数据范围

拆任务：

- 传用户本次输入
- 传当前宠物类型
- 不传全部任务、备忘、专注历史

下一步：

- 传当前未完成任务摘要
- 传任务标题、状态、进度、截止时间、最近更新时间
- 传当前宠物类型
- 不传备忘录全文、删除记录、全量历史

复盘：

- 传最近 7 天统计摘要
- 传总专注时长、专注次数、时间段分布、最常推进任务、最长一次专注
- 传当前宠物类型
- 不传所有原始 session 明细、备忘录内容、更久远历史

## 10. 本地持久化策略

第一期不直接上 SwiftData，先使用轻量 JSON 文件持久化。

原因：

- 当前模型已经是 `Codable`
- 改动小，能快速让数据重启后不丢
- 更适合优先验证首页 Agent 和宠物陪伴体验
- 不会因为数据层重构拖慢第一轮迭代

第一期要做：

- 新增本地存储服务
- App 启动时读取本地 JSON
- 如果本地没有数据，再加载 mock data
- 任务、备忘、专注记录、设置变化后自动保存
- 保存失败时不打断用户

暂不做：

- SwiftData
- Core Data
- 云同步
- 账号系统
- 后端业务数据同步
- 复杂数据迁移

## 12. 验收标准

本轮迭代完成后，应满足：

- 关闭重开 App 后，任务、备忘、专注记录仍在
- 首页不再像 AI 工具入口页
- 宠物成为首页主视觉和交互主体
- 用户可以在宠物聊天页自然输入「我不知道怎么准备面试」，宠物能识别并引导拆任务
- 用户输入「我不知道先做哪个」，宠物能推荐一个任务、理由和建议专注时长
- 用户输入「帮我看看最近状态」，宠物能生成最近 7 天复盘
- 后端没开时，App 核心功能仍可用
- 自伤、危险、违法、恶搞输入不会进入任务型 Skill
- 四个宠物回复风格明显不同，但都符合温和陪伴原则

## 13. 本轮迭代希望提升的产品目标

### 13.1 强化宠物陪伴感

让用户感受到不是在操作工具，而是在和一个小动物一起推进任务。

### 13.2 降低启动阻力

通过自然语言输入、拆任务、下一步建议，把「我知道要做但开始不了」转化为「先做一小步」。

### 13.3 减少效率工具压力感

首页不再强调未完成数量、逾期压力和强倒计时，而是强调正向积累和可恢复推进。

### 13.4 让 AI 服务产品主旨

AI 不作为炫技功能出现，而是内化为宠物 Agent 的能力，用来帮助用户记录、拆小、选择下一步、看见投入。

### 13.5 建立后续扩展基础

通过 Agent、Skill、输入 Guard、宠物人设和本地 fallback 的结构，为后续接入更丰富的 AI 能力、长期记忆和可能的 RAG 留出空间。

## 14. 当前已落地状态

截至本次整理，项目已经开始按上述方向落地：

- 首页已从单一「拆任务」入口调整为宠物陪伴区 + 四个功能入口 + 独立聊天入口
- 宠物对话已迁移到独立聊天页，避免首页看起来像输入框或聊天工具页
- 备忘录、待办、历史、专注设置等工具页已删去重复宠物说明卡，页面更偏工具化
- 点击宠物已有表情反馈和气泡文案反馈
- 聊天页输入会优先走后端 Pet Agent，自伤/危险输入在本地先拦截
- 后端不可用时，前端会回到本地 fallback，不影响首页基础使用
- 拆任务已改为聊天内展示可勾选步骤，用户点击「加入选中」后才写入待办，AI 不会直接创建待办
- 下一步建议可以带出「去专注 X 分钟」入口，但只进入专注设置页，不直接开始计时
- 下一步建议、拆任务会携带当前宠物类型，避免角色语气错位
- 四个宠物人设 Prompt 已从简单语气标签升级为设定档结构，包含风格定义、对话特点、说话示例和禁止事项
- `split_task`、`suggest_next_action`、`weekly_review` 已统一为内部 Skill 文件夹结构，分别包含 `SKILL.md`、`prompt.py`、`fallback.py`、`skill.py`
